# Flow комиссии: от кода до результата на ODS

## Overview

Комиссия E-CUP 2026 работает по схеме:
1. ODS Platform → комиссия получает submission → публичный MCP-валидатор → private leaderboard

## Публичный MCP-валидатор

Публичный MCP-валидатор — наш собственный сервис, который:
- Получает код (push в репо или upload)
- Запускает решение на нашем железе
- Прогоняет через оценочную функцию
- Публикует результат

Это **зеркало** публичной части ODS (не включает private test).

### Как работает

```
Пользователь push в ecup26-X
    ↓
GitHub webhook → MCP server (port 3200)
    ↓
MCP tool: validate_submission_package
    ↓
Checkout последний commit
    ↓
Run: python run.py --validate
    ↓
Compute metrics locally
    ↓
Return: { score, runtime, status }
    ↓
Post to ODS API (публичный leaderboard)
```

## Submission Format

### Matching

```csv
id1,id2,predict
1001,2002,0.87
```

### Quality

```csv
id,result
123,Товар содержит маркировку БАД на упаковке.бан
```

Формат result: `<комментарий 50-300 символов><вердикт>`.
Вердикт: `бан` или `не бан`.

### User Value

```csv
user_id,predict
1001,487.97
```

## Commission Mirror (наш MCP)

### Цель

Создать **зеркало публичной части** оценочной системы ODS.
Позволяет:
- Прогонять submission локально без загрузки на ODS
- Дебажить метрики и формат
- Сравнивать подходы без затрат на сабмиты

### Как использовать

```python
# В коде каждого репо:
# run.py --validate  # локальная валидация
# run.py --submit    # отправка на ODS (или наш MCP)
```

### Критерии успешного submission

- [ ] Файл существует и формат правильный
- [ ] Все id присутствуют (нет пропусков)
- [ ] Время исполнения < лимита
- [ ] Нет NaN/Inf в предсказаниях
- [ ] Значения в допустимых диапазонах

## Финальная отправка

После финализации кода:
1. Фиксируем финальный commit
2. Собираем архив (ZIP/TAR)
3. Загружаем на ODS
4. Выбираем 2 финальных решения (для задач 1 и 2 — контейнерные)
5. Для User Value — просто CSV
