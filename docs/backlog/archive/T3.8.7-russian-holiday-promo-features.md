## Context

The target window (2026-02-14..03-15) IS the gift season (Feb 23 + Mar 8 + Ozon's
combined sale), but our proxy fold (Jan 14..Feb 13) is a different season. Add
temporal holiday/promo/gift features derivable from event_date + GMV (no
category/region data available). Russia's concentrated holiday calendar (NY up
to 35% annual GMV) + Ozon's shifting platform promos are underused signals.

## GREEN

In build_features.py add per-user temporal features (all from rows <= ref_date):
1. Holiday/seasonal GMV shares (2025 windows, fully in the past):
   - gmv_share_ny (Dec15-Jan15), gmv_share_gift (Feb14-Mar8),
   - gmv_share_spring (Apr-May), gmv_share_summer (Jun-Aug),
   - gmv_share_promo_1111 (Oct23-Nov11), gmv_share_promo_bf (Nov14-Dec3)
2. Gift-buyer (targets the gift-season target window):
   - gift_buyer_2025 (GMV in Feb23-Mar8 2025 > 0),
   - feb_mar_gmv_2025 = log1p(GMV in that window)
3. New Year intensity:
   - dec_nov_ratio (Dec2025 GMV / Nov2025 GMV)
   - days_since_ny_activity (days from Jan11 2026 to last activity, clip >= -1)
