## Context

In v1 ablation (T3.6.12) `lgbm_ziln` was disabled because ZILN has 3 outputs
(z_prob, mu, sigma) and LightGBM 4.x regressor is single-output. The ZILN
math (P(y=0) + y|z>0 ~ LogNormal(mu, sigma)) is preserved in models/ziln.py
(T3.6.7) but not exposed to ablation.

This ticket splits ZILN into 3 independent single-output LightGBM regressors
and re-enables it in the ablation runner.

## GREEN

Three new wrappers in `src/ecup26_user_value/ablation/model_wrappers.py`:

1. `LightGBMZProbModel` — binary classifier, target = (y > 0).astype(float)
   - LightGBM `objective="binary"`, output via sigmoid -> P(y > 0), then z_prob = 1 - P
   - name: "lgbm_ziln_zprob"

2. `LightGBMMuModel` — regression on log1p(y) for y > 0
   - LightGBM `objective="regression"`, output is mu directly
   - name: "lgbm_ziln_mu"

3. `LightGBMSigmaModel` — regression on squared log-residuals
   - target: (log1p(y) - mu_target)^2 where mu_target is the empirical mean log
   - clipped to [1e-3, +inf) at predict time
   - name: "lgbm_ziln_sigma"

Composite `LightGBMZILNComposite` — orchestrates the 3 submodels:
- fit: train each submodel on its target
- predict(X): returns (1 - sigmoid(zprob_pred)) * exp(mu_pred + sigma_pred**2 / 2)
- name: "lgbm_ziln" (replaces the disabled stub)

Add `lgbm_ziln` to `ACTIVE_MODELS` in `scripts/ablation_matrix.py`.
Output: `docs/results/ablation_v2.csv` with extra rows (1 model x 3 LOO x 2 folds = 6).
