## Context

Per T3.7.2 comparison (2026-08-16): SegmentedBTYD achieves model_rmsle=5.5611
on holdout, but naive baseline is 3.1750 (lift = -0.75). Both models
systematically underfit — BTYD uses only (recency, frequency, monetary)
from 4 of 18 train columns.

Per meta-prompt T3.7.5 (Optimization Cycle #1): add 4 feature groups to
close the gap to naive baseline.

## GREEN

`src/ecup26_user_value/features/build_features.py` (new module):

1. **Calendar features** (per user-row):
   - `day_of_week` (0..6)
   - `month` (1..12)
   - `quarter` (1..4)
   - `is_weekend` (0/1)
   - `is_holiday_ru` (0/1) — Russian holidays 2025-2026

2. **Rolling window features** (per user, last N days before ref_date):
   - `gmv_avg_7d`, `gmv_avg_14d`, `gmv_avg_30d`
   - `orders_avg_7d`, `orders_avg_14d`, `orders_avg_30d`
   - `gmv_max_30d`
   - `n_active_days_30d`

3. **Cross-features** (interactions):
   - `recency_x_frequency` = (T - recency) * frequency
   - `recency_x_avg_order_value` = (T - recency) * monetary
   - `frequency_x_monetary` = frequency * monetary

4. **Customer tenure**:
   - `days_since_first_purchase` = (ref_date - first_event_date)
   - `is_new_customer` = (days_since_first_purchase < 7)

All features computed **only from training data**, no future leakage.
Reference date = max event_date in train_df.

Implementation: vectorized pandas, no row-iter loops.

## RED

`tests/test_features.py`:
- `test_calendar_features_shape`: build_features adds 5 calendar cols
- `test_rolling_window_no_future`: rolling features at ref_date use only past data
- `test_determinism`: same seed -> same features (byte-identical)
- `test_cross_features_finite`: all cross features non-NaN for active users
- `test_tenure_known_value`: days_since_first_purchase matches manual calc
- `test_holiday_flags_known_dates`: New Year, May 1, Russia Day -> 1
- `test_no_data_leakage`: ref_date features never use rows >= ref_date
