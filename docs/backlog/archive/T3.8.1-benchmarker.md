## Context

We already have `scripts/experiment_ensemble.py` (single-config A/B with a
cached walk-forward train). This ticket turns it into a proper benchmarker:
- Structure borrowed from the author's own `BenchmarkService`
  (`backend/src/application/benchmark_service.py` in diplomMagistrate):
  dataclass results + runner + `format_results_table` + CSV.
- Combinatorial search (curated grid + random) over the pipeline settings that
  are baked into the submission as fixed constants (NOT embedded in run.py).

## GREEN

`scripts/benchmark_t3.py` (new CLI):
1. Build/cache the walk-forward train once (`/tmp/bench_walkforward_train.parquet`).
2. Search space (baked into run_pipeline constants when a winner is found):
   - `n_estimators`: [50, 100, 150, 200]
   - `num_leaves`: [15, 31, 63]
   - `learning_rate`: [0.03, 0.05, 0.1]
   - `feature_fraction`: [0.7, 0.8, 1.0]
   - `bagging_fraction`: [0.7, 0.8, 1.0]
   - `min_child_samples`: [10, 20, 50]
   - `target_transform`: [log1p]  (tweedie rejected — worse on proxy)
   - `windows`: [(7,14,30), (7,14,30,60,90)]
3. Strategies: `--strategy grid` (curated Cartesian, ~30–60 configs)
   | `random` (N samples) | `optuna` (optional, MIT, dev-only).
4. Validation: walk-forward CV — 2–3 historical holdout windows, report
   mean ± std RMSLE (not a single proxy — protects against drift).
5. Output: ranked table (config -> RMSLE, mean/median, time) + CSV + best
   config JSON (`docs/results/benchmark_best.json`).
