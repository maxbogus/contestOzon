`scripts/tune_hyperparams.py` (new CLI):

1. Search space (6 params):
   - `BTYDBaseline.penalizer_coef`: [0.001, 0.01, 0.1, 1.0]
   - `BTYDBaseline.time_period_days`: [7, 14, 30, 60]

   - `LightGBMRegressorMSE.num_leaves`: [7, 15, 31, 63]

2. Search algorithm: grid search (Option A — exhaustive) or Optuna
   TPE sampler (Option B — 50 trials, faster). Default: grid search
   (4 * 4 * 5 * 4 * 4 * 4 = 5120 combinations). Reject Optuna to avoid

   predict on holdout, compute model_rmsle.

4. Output: top-10 configs by model_rmsle (mean +/- std across folds).

## Cycle #2 Result (DEFERRED)

**Outcome**: All 81 configs on 10k user subsample evaluated in 2273s
(37.9 min). Top-1 RMSLE = 2.3668, default config RMSLE = 2.3687.

**Why deferred (not done)**:
- Improvement top-1 vs default: **0.08%** (< 2% acceptance gate).
- Default config is in top-10 (rank #6): LightGBM defaults are already
  near-optimal for this dataset.
- Wall time 37.9 min > 30 min budget.

**Key diagnostic**:
- LightGBM fit on 10k user features takes **0.1s per config**.
- **Bottleneck is `bootstrap_ci`**, not LightGBM fit: 50 boot samples
  x 250k val users = 12.5M operations per config (~28s).
- For future tuning: reduce `n_boot` to 10-20, or subsample val users.

**Re-open criteria**:
- After more features added (T3.7.3+) or different model type.
- After fixing bootstrap CI performance (parallelize or subsample).
