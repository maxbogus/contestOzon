## Механика прорыва

1. **Таблица недо-предсказывает** (mean ~38.3): RMSLE-оптимум на walk-forward
   origins систематически занижает агрегат (T3.13.A2).
2. **Нейро перепредсказывает** (w240 mean 49, w409 mean 45): «помнит» Q4-пик.
3. **Гибрид** `expm1(w·log1p(нейро) + (1−w)·log1p(таблица))` при малом w
   (0.1-0.25) поднимает mean к LB-оптимуму ~39.9-40.0 и добавляет
   разнообразие ранжирования → выигрыш у обоих одиночек.
4. **Окно w409** (вся история) калибрует уровень правильнее, чем w240
   (видит полный годовой цикл спад→пик→спад).

## Грабли (инженерные уроки)

- **OOM на 8GB VRAM**: hidden=256 с batch=512 не влезает (активации GRU
  ~3.4GB при L=409). Фикс: `batch=256 if hidden>=256 else 512`.
- **OOM RAM при параллельном запуске**: инференс (5.8-6.5GB X) + свип-тренинг
  (6GB+) вместе валят 30GB RAM → запускать последовательно.
- **Таймауты**: transformer w360/w409 — 5ч лимит не хватает (O(L²)).
- **Остаточные процессы**: pkill sweep не убивает дочерний
  experiment_neural_wf.py → проверять nvidia-smi перед инференсом.

# T3.20 — Новые архитектуры (Mamba / RWKV / xLSTM), сессия 2026-08-30..31

> Итог сессии: все три новые архитектуры (pure PyTorch, self-implemented) НЕ бьют
> GRU. Нейро-потолок подтверждён: gru409v2_w0.3 = LB 1.650366. Батч 15 (5
> финальных сабмитов) подготовлен. Ключевые находки — производительность,
> численная устойчивость, инженерные грабли.

## 1. Что реализовано (R1: pure torch, self-impl, d_in=16)

| Класс | Архитектура | Скан |
|---|---|---|
| `MambaBlock` / `SequenceModelMamba` | S6 selective SSM (conv + dt/B/C + scan + gating) | chunked cumsum → **Hillis-Steele (division-free)** |
| `RWKVBlock` / `SequenceModelRWKV` | v4-style token-shift time-mix + channel-mix | параллельный cumsum (константный decay) |
| `mLSTMBlock` / `SequenceModelXLSTM` | xLSTM матричная память (exp-gate + normalizer) | chunked cumsum (forget floor 0.9) |

Инфраструктура: `--model mamba|rwkv|xlstm` в `experiment_neural_wf.py`,
`sweep_neural_ssm.py` (resume-safe CSV), `tests/test_neural_ssm.py` (24),
torch.compile (reduce-overhead), TF32.

## 2. Производительность (RTX 5060 8GB, torch 2.13.0+cu130)

Бенч: fwd+bwd+step, batch=const, L=409, d_in=16, hidden=128, layers=2.
мин/эпоху = 1.75M сэмплов (7 origins) / batch × ms/1000/60.

| Модель | batch | torch.compile | ms/batch | мин/эпоху |
|---|---|---|---|---|
| GRU (cuDNN, референс) | 512 | — | ~45 | ~2.7 |
| RWKV | 512 | нет | 269–286 | ~15 |
| RWKV | 512 | да | 125–143 | **8.1** |
| xLSTM h32 (4×32) | 128 | да | 104 | 23.6 |
| xLSTM h16 (8×16) | 192 | да | 109 | 16.5 |
| Mamba e1 (cumsum) | 128 | да | 95 | 21.7 |
| Mamba e1 (cumsum) | 256 | да | 198 | 22.6 |
| Mamba e2 (cumsum) | 96 | да | OOM | — |
| Mamba HSS e1 | 96 | нет | 424 | **128.7** |
| Mamba HSS e1 | 96 | да | 1394 | **423.5** |
| Mamba HSS e1 | 64 | да | 940 | **428.4** |
| Mamba sequential (no compile) | 64 | нет | ~400 | ~59 |

Наблюдения:
- **torch.compile даёт 2.3–4.4×** (RWKV 269→125ms; xLSTM 360→104ms; Mamba 665→95ms
  на cumsum-версии). Inductor фьюзит elementwise-цепочки; profile: elementwise
  (256,409,128) ~397µs/op, sgemm ~550µs.
- **GRU ~5× быстрее** любой pure-torch рекуррентной реализации — cuDNN fuse всего
  рекуррентного прохода в 1 kernel.
- Hillis-Steele (division-free) на 8GB — неприемлем (128–428 мин/эпоху): O(C·log C)
  комбайнов с gather/where на (B,32,128,8) каждый уровень.
- **VRAM (HSS e1, без compile)**: b32=2.17GB, b64=4.24GB, b96=6.34GB — 0.068 GB/batch.
- Реальные тайминги эпох (вкл. np.load 7 origins ~2–3 мин + val-eval): RWKV ~13 мин,
  xLSTM ~26–31 мин, Mamba (cumsum) ~35 мин. Полные xLSTM-прогоны 20ep: lr0.0001 ≈ 6ч,
  lr0.0003 ≈ 10ч.

## 3. Численные находки (главное)

| Проблема | Симптом | Причина | Статус |
|---|---|---|---|
| Mamba chunked-cumsum | fold-B 1.9982 @ ep1, train_mse 2.3e9 | backward `1/cp²` ~ 1e27 (cp = cumprod(exp(dt·A)) → e^-32) | ❌ ВЗРЫВ |
| Mamba Hillis-Steele | корректен (fwd 2.4e-7, grad 4.8e-7) но 128–428 мин/эпоху | O(C·log C) + память 0.068 GB/batch | ❌ МЕДЛЕННО |
| RWKV | fold-B 2.2888 @ ep3 (train_mse 5.53 — сходится!) | нет val-обобщения (v4-style time-mix не переносит режим) | ❌ МЁРТВ |
| xLSTM forget floor 0.3 | латентный взрыв 1/cp² до 1e33 | f → 0.3 ⇒ cp → 1.85e-17 | ✅ фикс: floor **0.9** (cp ≥ 0.034) |

Урок: в параллельных сканах через cumsum/cumprod **division = 1/cp² в backward** —
градиенты взрываются даже если forward конечен (обходной путь: division-free
сканы медленны, константный decay (RWKV) стабилен но не учит режим).

## 6. Грабли (инженерные уроки сессии)

1. **RAM OOM 30GB** (упал VSCode): `torch.tensor(X)` удваивал 6.5GB/origin → `torch.from_numpy` zero-copy. Пик ~20GB → ~13GB.
2. **CUDA-graph overwrite**: `torch.compile(reduce-overhead)` переиспользует буфер выхода; накопление `parts` без `.clone()` → RuntimeError. Фикс: `.clone()`.
3. **TF32 warning** → `torch.set_float32_matmul_precision("high")`.
4. **`_orig_mod.` prefix**: state_dict скомпилированной модели не грузится в чистую → strip при load + `getattr(model,"_orig_mod",model)` при save.
5. **Partial-batch recompile**: compile-графы пере-кэпчются на неполный батч (~1-2 мин) → truncation train + padding val до полного `bs`.
6. **`--timeout 12h`** сломал int-парсер sweep → секунды.
7. **Parallel cumsum-сканы**: см. §3 — division в backward опасен.
8. **Не запускать инференс+тренинг параллельно** (RAM), и **убивать старый процесс ДО запуска нового** (иначе новый мгновенно OOM-killed без трейсбека).
9. mamba-ssm (CUDA-ядра) несовместим с torch 2.13+cu130; через Docker — отдельный трек.
