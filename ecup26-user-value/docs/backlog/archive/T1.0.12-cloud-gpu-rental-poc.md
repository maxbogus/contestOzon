## Context

Local RTX 5060 + CPU offload is fast enough for 500K test items (~5 min). But full-corpus encoding (13M items) or multiple iterations may require cloud GPU.

Trigger conditions in ADR-001-bi-encoder-inference-strategy.md.

## Plan

1. **Provider comparison** (30 min):
   - RunPod: H100 spot ~$1.5/h, A100 ~$0.8/h
   - Vast.ai: H100 ~$1.0/h, A100 ~$0.5/h
   - Lambda Labs: A10G ~$0.6/h, A100 ~$1.1/h
2. **One-shot POC** (1 h):
   - Spin up cheapest H100 spot
   - Run full-corpus encoding (13M items)
   - Measure wall time + cost
3. **Decision**:
   - If <$5 per full encode → keep local, use cloud for final submission only
   - If >$5 per encode → optimize local setup or accept local
4. **Cache strategy** (30 min):
   - Where to store embeddings (S3? local NFS?)
   - Invalidation rule (model version, item catalog version)

## Closure note (2026-08-15)

**Status: skipped — local is sufficient.**

Verified locally on RTX 5060 8GB + CPU offload (T1.0.10 implementation):
- 500 items encoded in 26.5s (~53ms per item).
- For 500K items: ~7.4h one-time encode — covered by T1.0.11 cache.
- For inference pipeline (Docker runtime): embeddings loaded from cache,
  not re-encoded at submission time.
- T1 Private limit (13 min) applies to **inference**, not offline encoding.
- Cloud POC would only help if we needed to re-encode full corpus daily,
  which we do not.

Conclusion: no cloud GPU rental needed. ADR-001 + T1.0.10 + T1.0.11
provide sufficient infrastructure for T1 submission.
