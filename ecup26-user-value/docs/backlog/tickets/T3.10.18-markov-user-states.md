## Hypothesis

В подарочный период меняются не количества, а ВЕРОЯТНОСТИ переходов:
B(Cart->Buy) 20% -> 60%, B(Browse->Idle) 70% -> 30%. Табличная модель видит
«хаос» цифр; матрица переходов ловит фундаментальный сдвиг паттерна. Фича
`gift_transition_boost` кодирует этот сдвиг с колоколом Гаусса вокруг праздников
(14 фев / 8 марта).

## E0 — Инфраструктура: состояния + 2 матрицы (с системными проверками)

- 4 состояния по дневным флагам: dormant (нет строки) / browsing (search|cat,
  без корзины) / carting (to_cart>0, без заказа) / buying (to_ord>0).
- Матрица A (обычные дни) и Матрица B (подарочный сезон 2025: 14.02-08.03.2025).
- СИСТЕМНЫЕ ПРОВЕРКИ (тесты, не «посмотрел глазами»):
  1) строки матриц суммируются в 1 (стохастичность);
  2) B(Cart->Buy) > A(Cart->Buy) (гипотеза 20%->60%);
  3) покрытие состояний (все состояния присутствуют в A и B);
  4) leak-check: матрицы и фичи используют только факты <= ref_date.

## E1 — Фича gift_transition_boost

- `days_to_holiday` = знаковое расстояние до ближайшего из (14.02, 08.03),
  отрицательное после праздника.
- `gift_activation_boost = (P_B(state->Active) - P_A(state->Active)) * exp(-days_to_holiday^2)`,
  где Active = browsing+carting+buying, state = текущее состояние юзера на ref_date
  (dormant = без активности 7+ дней).
- ИСТОЧНИК (E0, полные данные): Dormant->Active A=0.211 -> B=0.363 (1.72x) -
  главный драйвер праздника. Cart->Buy БЕСПОЛЕЗЕН (A=0.107 > B=0.101).
- Добавляется поверх лучшего стека (бленд + акторные).

## E0.5-E0.7 findings (2026-08-19)

- N-grams (2-3 active-state paths): buy_rate FLAT ~0.705 (spread 0.001-0.002) -
  active-state paths do NOT predict purchase.
- Wake-up chains 13-18: ALL FLAT (dormant_days, first step, intensity, holiday,
  check) - post-wake-up behavior is deterministic ~70.5%%.
- Chain 20 time-to-buy: conditional buy_rate declines GRADUALLY (0.705->0.651->
  0.621->...->0.467 over 7 days) - no sharp cliff; already captured by recency.
- SYNTHESIS: only Dormant->Active wake-up RATE (1.99x gift / 1.81x NY) is the
  spike signal. gift_activation_boost = (dormant user) x (P_B-P_A dormant->active)
  x gaussian - encode the WAKE-UP RATE, not post-wake-up details.
